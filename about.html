Data engineering with a platform mindset.

How I work

Practical engineering, built for the people using it.

I care about the unglamorous details that make data systems trustworthy: version control, tested deployments, sensible access, and compute that isn’t left running.

01

Everything in version control

Jobs, infrastructure, and permissions belong in code that can be reviewed and redeployed, not in a UI.

02

Build it once for everyone

Shared templates and patterns beat one-off fixes, so every team gets the same tested path to production.

03

Prove it before cutover

A migration isn’t done until the new system’s output has been checked against the one it replaces.
